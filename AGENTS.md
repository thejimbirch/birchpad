# Agent guide for Birchpad

Birchpad is five Logi Actions SDK plugins (C#, .NET 10, macOS) for the Logitech MX Keypad: BirchpadAgentHub and BirchpadHerdr (universal), BirchpadClaude, BirchpadCodex, and BirchpadITerm.
Read `README.md` for setup and `docs/workflow-design.md` for the approved key design before changing any key or page.

## Layout

- `src/Birchpad.Core`: all logic without a Logitech dependency; unit tested in `tests/Birchpad.Core.Tests`.
- `src/Shared`: code compiled into every plugin (`MenuFolder`, `TileRenderer`, `AppItems`, `PromptsFolder`, `SlashCommands`).
- `src/Birchpad<Name>Plugin`: one plugin each; `package/` holds its manifest, icon, and shipped default profile.
- `hooks/`: installers that edit `~/.claude/settings.json` and `~/.codex/hooks.json`, and the scripts they install.
- `tools/`: `package.sh`, `deploy.sh`, `profiles.py`, `make_icons.py`.

## Build, test, deploy

```sh
export DOTNET_ROOT=/opt/homebrew/opt/dotnet/libexec
export PATH=/opt/homebrew/opt/dotnet/bin:$PATH:$HOME/.dotnet/tools
dotnet test tests/Birchpad.Core.Tests
tools/deploy.sh BirchpadClaude        # Release build copied over the installed plugin, then reloaded
tools/package.sh                      # verified .lplug4 files in dist/
python3 tools/profiles.py write       # default home pages; check validates every key
```

The plugins are installed from their packages, not linked; `deploy.sh` updates them in place with no install prompt.
A first install, or a reinstall, is `open dist/<Name>.lplug4` and the user accepts the Options+ prompt.
`logiplugintool install` and `uninstall` fail against this service ("cannot start"); do not rely on them.
Check a deploy in `~/Library/Application Support/Logi/LogiPluginService/Logs/plugin_logs/<Name>.log`.

## Design rules

- No key is bound to one item; every list is a folder filled at run time.
- In folders, Back is the top-left key and More is bottom-right; the rules are in `Birchpad.Core.Menu.MenuLayout`.
- Claude's layout is the guide; an equivalent key in ChatGPT or iTerm takes the same position.
- Sessions and Next waiting are scoped to the profile's app; iTerm shows both agents.
- Home pages ship as each plugin's `DefaultProfile70mac.lp5`, generated by `tools/profiles.py`.

## Traps

- The installed PluginApi is built for .NET 10; target `net10.0`. LogiPluginTool needs `DOTNET_ROLL_FORWARD=Major`.
- Every plugin needs a `ClientApplication` subclass, even a universal one, or it fails to load with no reason logged.
- Removing or renaming an action breaks that key in every existing profile, and Options+ never refreshes an existing profile from a new default.
  Uninstalling a plugin leaves its app entry and profile behind. Warn the user before such a change.
- Options+ cannot import a profile for a plugin's app (`@_birchpad...`); see `docs/logitech-bug-report.md`. Defaults apply only when a plugin is installed with no existing profile for its app.
  General profiles (`@_defaultmac`) and profiles bound to a plain app's bundle ID do import, so new layouts ship as those (`tools/profiles.py` `GENERAL`).
- Actions load before `Plugin.Load`, so an action that subscribes to a service Load creates never hears it; raise change events from the plugin object instead (`HubChanged`, `HerdrChanged`).
- The host adds its own folder Back key unless `GetNavigationArea` returns `EncoderArea`.
- Folder pages are built on a worker thread; never do file, process, or HTTP work on the host thread or under `MenuFolder`'s lock.
- Start child processes with `ProcessRunner` or `ChildProcess`, never `Process.Start`, which puts them in the plugin service's process group (`CreateNewProcessGroup` does nothing on macOS).
  A git that `codex app-server` ran to check git-sourced plugin marketplaces sent SIGHUP to that group, and the service died with no log line, crash report, or exception.
  `log show --predicate 'process == "launchd"'` names the signal and its sender ("exited due to SIGHUP | sent by git[pid]").
- Claude Desktop accepts only fixed `claude://claude.ai/` routes (`chat`, `project`, `new`, `settings`, `tasks`, `cowork`, `customize`, and a few more).
  Pages without a route (Artifacts, Design, Scheduled) are opened by pressing the sidebar button by name (`MacAutomation.PressButton`).
- Installed profiles live in `~/Library/Application Support/Logi/LogiPluginService/Applications/Loupedeck70/@_birchpad<app>/Profiles/<id>/ProfileInfo.json`; read them to see which action IDs a keypad's keys point at.
- Service logging turns on when `enablelogs`, `forcelogs`, or `enableverbose` exist in `~/Library/Application Support/Logi/LogiPluginService/`, after a service restart.
- Agent Hub listens only on 127.0.0.1:8766 and refuses posts without `Content-Type: application/json` or with an `Origin` header.
- Codex hooks must be re-trusted in `codex` `/hooks` whenever their command changes.
- Read only IDs, titles, paths, and token counts from Claude and Codex local files; never print message content.
- The Herdr plugin talks to herdr's socket, never its CLI; test against `herdr --session <name> server`, never the default session.

## Conventions

- Plugin code follows the SDK template style (`String`, `Boolean`, braces on namespaces); core code uses modern C#.
- Markdown: one sentence per line, no em dashes.
- Commits: conventional commits with an `Assisted-by:` trailer; ask before committing or pushing.
